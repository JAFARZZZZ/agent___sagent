# Chat-first shopping planner status

The homepage `/` is the existing Persian conversation interface. It loads category metadata and saved session state, not map clusters or offers. `/map` opens only after a product is selected or added to a basket. The map uses `/api/sessions/{id}/map-offers`; it returns relevant offers, and never loads the whole dataset at startup. The previous full-catalog map backend remains available for diagnostics, but is not called by the customer homepage.

Baskets are stored in the existing `sessions` table. Up to 12 products can be added, removed and assigned a preferred offer. The backend validates each product/offer relationship. Optimization uses actual offers, returns cheapest, fewest-stops and balanced options, enforces a recorded total budget when set, and marks unresolved items. It samples at most 15 lowest offers per item and keeps 300 diverse partial combinations; therefore it is a bounded heuristic, not a guaranteed global optimum. If the user selected a starting point, stop order and straight-line distance are calculated. No road time is claimed.

Price freshness is calculated from `last_price_changed_at` using timezone-aware UTC comparison. Offers 30 or more days old are marked stale; missing/malformed timestamps remain unknown. The existing simulated seller confirmation table stores price-update requests, while request metadata remains in the session. Original offer prices are not overwritten.

Browser test `python -m scripts.chat_first_smoke` passed at 320, 390 and 1440 pixels: initial chat load made no map/offer request, then a real product was found, added to a persistent basket, shown on the relevant map and returned to chat. The backend planner test used three actual products and confirmed every option covered all three.

Remaining work: automated parsing of multiple item intents from one natural-language sentence, price verification state lifecycle beyond existing simulated responses, full conversation listing/renaming/deletion and secure anonymous identity, route service integration, comprehensive mobile/visual tests, live OpenAI behavior (previous provider calls timed out), external product image and map tile availability. A basket is functional through manual selection; the AI agent is not yet a reliable automatic multi-item planner. Route optimization is approximate straight-line ordering.
